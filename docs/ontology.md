# Ontology

This document names the things uncoded deals with and says what the words mean,
while [the architecture](architecture.md) says where each thing lives in the
code.

The ontology is an enduring part of the project. Changes to the code, the
documentation, the skills and the specifications should keep these meanings, or
update this document deliberately.

The product's name is uncoded, in lower case even at the start of a sentence.

Each definition ends with the words it replaces. Those words are not used for
the concept, in code, documents, skills or issues.

The dated specifications record the design of particular pieces of work. Where
their words conflict with this document, this document is authoritative.

## Definitions

### Project and project directory

A **project** is the codebase uncoded is configured in. Its **project
directory** is the directory that holds its configuration file. Generated files
are written relative to the project directory.

The project directory is not necessarily the top of a Git repository. A
subproject in a monorepo can have its own project directory, and a project need
not be in Git at all.

Replaces: "project root", "repository root", "host project".

### Configuration file

The **configuration file** is the `pyproject.toml` or `.uncoded.toml` that
configures uncoded for a project.

Replaces: "config file".

### Root, source root and doc root

A **root** is where uncoded starts building a tree.

A **source root** is a directory listed in `source-roots`. The namespace map
builds a tree of directories, files and symbols from it.

A **doc root** is a directory or a single Markdown file listed in `doc-roots`.
The docs map builds a tree of headings from it. A single file is a root because
its headings form a tree.

Replaces: "root type", which is "source roots" or "doc roots".

### Index, code index and documentation index

The **index** is everything uncoded generates under `.uncoded/` for agents to
navigate a project. It has two parts:

- the **code index**, which is the namespace map and the stubs; and
- the **documentation index**, which is the docs map.

Replaces: "symbol index", which is the code index.

### Namespace map

The **namespace map** is the code index's file `.uncoded/namespace.yaml`. It
lists every directory, file and symbol under the source roots as one tree.

### Stub

A **stub** is the code index's file for one Python file, at the same path under
`.uncoded/stubs/` with a `.pyi` suffix. It holds the file's imports and each
symbol's signature or annotation, without bodies.

### Docs map

The **docs map** is the documentation index's file `.uncoded/docs.yaml`. It
lists every Markdown file under the doc roots and nests each file's headings as
a tree.

Replaces: "doc map", "heading map", "heading outline".

### Generated file

A **generated file** is any file `sync` writes: the index's files, the installed
skill files and `.uncoded/.gitignore`.

Replaces: "artefact", "index artefact", "navigation artefact".

### Provenance marker

The **provenance marker** is the line that says a file was generated by uncoded
and must not be edited. Every generated file carries it. The code defines it
once, as `GENERATED_MARKER`.

### Current and stale

A generated file is **current** when it matches what `sync` would write now, and
**stale** when it does not. The index is current when all its files are.

Replaces: "up to date", "matches a fresh build".

### Symbol

A **symbol** is a name in Python source that names a definition: a class, a
function, a method, a module-level assignment, a class attribute or a `type`
alias. Directories and files are not symbols.

Replaces: "module constant", which is a module-level assignment.

### Definition

A **definition** is the code a symbol names, as Python's grammar defines it. For
a function or class, that runs from its first decorator to the end of its body.
`body` prints a symbol's definition.

Replaces: "body" and "source body" for what `body` prints. In Python's grammar a
body is only the indented block.

### Name path

A **name path** says which symbol `body` or `refs` means: `name` for a top-level
symbol, or `Class/member` for a method or class attribute. The term is the one
LSP-based tools such as Serena use.

Replaces: "symbol path".

### Reference

A **reference** is a place where a symbol's name appears as that symbol: its
definition, an import of it, or a use of it. `refs` prints each reference as
`path:line:column`. This matches the references a language server returns when
asked to include the declaration.

### Skill

A **skill** is a set of instructions uncoded generates for an agent to load. The
**uncoded skills** are `uncoded-code-navigation`, `uncoded-doc-navigation` and
`uncoded-consistency-review`. The **navigation skills** are the first two.

An **installed skill file** is a skill's `SKILL.md` in the project. A **skill
source** is the Markdown file in uncoded's package that a skill is rendered
from.

Replaces: "package resource", "skill instructions", and "source" for a skill
source.

### Consistency review

The **consistency review** is the review that `uncoded-consistency-review`
carries out. It reports disagreements between two claims about one concept, with
the evidence for each.

### Agent

An **agent** is an AI coding agent working in a project, such as Claude Code or
Codex.

Replaces: "coding agent" and "AI coding agent", except to introduce the term.

### Developer

A **developer** is the person who sets up uncoded in a project. They write the
configuration file, run `sync` and `check`, and commit the installed skill
files. The documentation addresses them as "you".

Replaces: "user", "contributor".

## Relationships and rules

### The project directory and its roots

uncoded finds the configuration file by walking up from the current directory to
the nearest `pyproject.toml` or `.uncoded.toml`. That file's directory is the
project directory.

Every root must sit inside the project directory after symbolic links are
resolved.

### The index and its roots

The code index exists while at least one source root is configured, and the
documentation index while at least one doc root is. The two are independent.
When the last root of one kind is removed, the next `sync` removes that part of
the index and the skills that go with it.

The code navigation skill and the consistency review go with the source roots.
The doc navigation skill goes with the doc roots.

### Keeping generated files current

`sync` writes each generated file that is stale and leaves the rest. `check`
writes nothing, and reports whether every generated file is current.

The index is local to the developer's checkout and is not committed. The
installed skill files are committed.

### Symbols and references

A name path has one segment or two. Deeper name paths are not supported.

A symbol's references include its definition, so a symbol always has at least
one. A symbol is unused when every reference to it is part of its own
definition. An unused property with a setter, or an unused function with
overloads, still has more than one such reference.
